  A `tools/_template.html` with the VIZ markers, embed contract, mobile quality tiers, reduced-motion check and a stub `shouldRun`/`render` already wired — so a new tool starts compliant instead of starting as a copy of the last one. *This is what stops the drift recurring; the runtime alone doesn't.*

- [ ] **6b. Close the `accel`/`Veff` test gap.** *(still open, and now wider)*
  Both close over module-level `mu`/`L`/`aSpin`/`Efix`, so the extractor can't rebind them. `mk(a, E, L, mu)` in the Kerr suite re-derives the formulas in the test, and a source-regex guard (`source Veff matches the tested Kerr form`) checks the tool still matches — so `accel = −½ dVeff/dr` and the a→0 reduction are verified against the *test's* copy, not the shipped code. Refactor to pure `f(r, mu, L, a, E)` so the numerical assertions bind to the real functions. *Deliberately kept out of the step-4 migration and out of the Kerr work — both were already large, and mixing a physics refactor in would have made any regression hard to localise.*

- [ ] **5. `tools/` manifest + static gallery.** *(defer until tool #4)*
  One JSON array — slug, title, blurb, tags, embed height — generating the gallery and the homepage Tools section.
  **This is the resource fix, not a convenience feature.** The homepage currently embeds every tool as a live iframe; at six tools that is six documents, six canvases, and six rAF loops on one mobile page. Target: static cards linking to standalone pages, at most one live embed on the homepage. Gallery cards must be static thumbnails — never a grid of live iframes.

**2026-08-14**

- [x] **Hero figure replaces the chirp band.** One black hole bisected: a single gravitational wave leaving along the axis on the left, a conical accretion flow with particles accelerated at its boundary on the right. Cartoon treatment, light ground, no text — generated by `tools/mkfigure_light.py` (`variant_hero`) and **inlined**, so the page still fetches nothing but the font. Its colours are the site's CSS custom properties, so it follows the theme: `--ink` draws the outlines and flips light on a dark page, while `--field` fills the hole and is near-black in both palettes. The generator emits both a hard-coded light build and a themed `hero-inline.svg`; only the themed one goes in the page, and a check fails if a literal hex ever reappears in the figure. Costs **8.3 KB gzipped** on index.html (12.5 → 20.8). 16 new checks, each mutation-tested.

- [x] **Search and social preview on all three pages.** `description`, Open Graph, `twitter:card`, `canonical`, `theme-color`, and an inline SVG favicon — previously zero of these existed, so a shared link rendered as a bare URL. The three 1200×630 cards in `assets/og-*.jpg` (227 KB total) are **generated from the live pages** by `tools/og-card.html` and `tools/og-tool.html`, which load the real widget in a same-origin iframe and crop to a measured element rect, so a card cannot drift from what the page draws. Two headless traps documented in [TOOLS.md](TOOLS.md): Chrome reports `prefers-reduced-motion: reduce` (the geodesic tool therefore starts paused, and the card showed a motionless particle), and `--virtual-time-budget` advances the clock **without ticking rAF** — 20 s of virtual time fired 6 frames — so the orbit trail is built by calling the tool's own `step()` directly, which is exact and reproducible. The favicon is the hero chirp with the cycle count cut until it survives 16 px, inlined as a `data:` URI so the pages still fetch nothing but the font. `theme-color` is driven by the theme script rather than a media query, since a media query keeps reporting the system colour after an explicit toggle. 56 new checks, each mutation-tested.
